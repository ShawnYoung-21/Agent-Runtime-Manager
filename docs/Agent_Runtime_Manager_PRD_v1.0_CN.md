# Agent Runtime Manager

# 产品需求文档（PRD）v1.0

版本：v1.0 状态：Draft

------------------------------------------------------------------------

# 1. 产品愿景

Agent Runtime Manager 是一个面向本地 AI Agent 的 CLI First
运行管理工具。

目标是在个人计算设备中，为 AI Coding Agent 提供：

-   任务运行保障
-   Agent 生命周期感知
-   运行环境状态管理

使开发者可以在移动设备场景下可靠执行长时间 Agent 任务。

------------------------------------------------------------------------

# 2. 背景

AI Coding Agent 正逐渐从辅助工具变为执行型工程伙伴。

典型流程：

用户定义目标

↓

Agent 分析项目

↓

修改代码

↓

执行测试

↓

修复问题

↓

完成任务

当前 Agent 通常直接运行于操作系统之上：

AI Agent

↓

Operating System

↓

Hardware

中间缺少 Runtime Management Layer。

------------------------------------------------------------------------

# 3. 核心问题

当前本地 AI Agent 缺少运行时保障能力：

-   长时间任务可能因为系统状态变化而中断
-   用户无法放心离开电脑
-   系统无法根据 Agent 生命周期动态管理资源

------------------------------------------------------------------------

# 4. 目标用户

主要用户：

使用本地 CLI AI Coding Agent 的开发者。

第一阶段目标用户：

-   Claude Code 用户
-   Codex CLI 用户

------------------------------------------------------------------------

# 5. 核心使用场景

## 场景一：移动设备长任务执行

开发者：

-   Windows 11 笔记本
-   电池模式
-   Claude Code / Codex CLI 正在执行任务

突然需要离开：

-   合上屏幕
-   不连接电源

期望：

Agent 继续运行，回来后查看结果。

------------------------------------------------------------------------

## 场景二：主动开启保护模式

用户提前知道需要离开。

主动开启 Runtime 保护。

系统进入：

Agent 运行保障状态。

------------------------------------------------------------------------

## 场景三：任务结束释放资源

Agent 完成任务。

Runtime：

-   识别任务结束
-   释放保护状态
-   恢复正常系统资源管理

------------------------------------------------------------------------

# 6. 产品定位

本产品不是：

"防睡眠工具"。

而是：

"面向 AI Agent 的本地执行运行管理层"。

核心关系：

AI Agent

↓

Agent Runtime Manager

↓

Operating System

↓

Hardware

------------------------------------------------------------------------

# 7. MVP 定义

## 支持 Agent

第一阶段：

-   Claude Code CLI
-   Codex CLI

后续：

-   Kimi Code CLI
-   Gemini CLI
-   Aider
-   OpenCode

------------------------------------------------------------------------

## Agent 状态

MVP 只关注：

-   Running
-   Finished
-   Stopped

不追求复杂任务理解。

------------------------------------------------------------------------

## MVP 核心能力

-   Agent 运行识别
-   Runtime 保护模式
-   基础生命周期管理
-   电源状态感知
-   Sleep 状态感知
-   网络状态感知
-   CLI 状态查看

------------------------------------------------------------------------

# 8. 非目标范围

MVP 不实现：

-   GUI Dashboard
-   Desktop Agent
-   云端 Agent
-   多 Agent 调度
-   高级自动恢复
-   完整任务理解系统

------------------------------------------------------------------------

# 9. 产品原则

## 原则一：CLI First

优先服务开发者终端工作流。

## 原则二：可靠性优先

先解决 Agent 长任务不中断。

## 原则三：生命周期驱动

根据 Agent 状态管理系统资源。

## 原则四：复用优先

优先利用已有系统能力和开源生态。

------------------------------------------------------------------------

# 10. MVP 验收标准

-   Claude Code CLI 可以被管理
-   Codex CLI 可以被管理
-   用户可以开启保护模式
-   合盖 + 电池模式下任务持续运行
-   Agent 完成后释放保护
-   用户可以查看运行状态

------------------------------------------------------------------------

# 11. 后续演进方向

-   更多 CLI Agent
-   Desktop Agent 支持
-   更细粒度 Agent 状态
-   自动恢复
-   多 Agent Runtime
-   云端协同

------------------------------------------------------------------------

# 总结

Agent Runtime Manager 的目标：

构建 AI Agent 与操作系统之间缺失的运行管理层。

不是阻止电脑睡眠，而是让系统根据 Agent 生命周期智能管理运行环境。
